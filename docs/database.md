# Database

Postgres on Supabase. The schema is built only by the migrations in `supabase/migrations`, which run
in filename order. `npm run db:reset` rebuilds a local database from them plus `supabase/seed.sql`
(demo data, local only). `npm run db:types` regenerates `src/types/database.ts` after a change.

The database enforces the marketplace's rules itself, so they hold whichever client calls it (the
website, `/api/v1`, a future app using the Supabase client directly, or a bug in server code):

- **Row level security is on for every table.** Every policy is written from the signed-in user's
  point of view (`auth.uid()`).
- **Column privileges** limit what clients can read and write even inside rows they can see (for
  example, `bookings.address_line`, `payments.checkout_url` and `messages.shares_contact` are never
  readable by clients, and prices, statuses and moderation fields are never writable by them).
- **Triggers** check every status change against the allowed transitions, keep history tables
  append-only, and refuse bookings for businesses that aren't open.
- **The service role** (`SUPABASE_SERVICE_ROLE_KEY`) is used only in server code for admin and system
  work, and every admin change is written to `admin_actions`.

Money is stored as whole kobo (`bigint`, `*_minor` columns), never as decimals. Times are
`timestamptz`; the app shows them in Lagos time.

## Tables by area

| Area          | Tables                                                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Accounts      | `users` (one per auth user: role, status), `customer_profiles`                                                                       |
| Businesses    | `businesses`, `business_services`, `service_areas`, `business_availability`, `business_portfolio`, `service_categories`              |
| Verification  | `business_verifications` (documents), `verification_requests`                                                                        |
| AI Concierge  | `ai_conversations`, `ai_messages` (the customer and the AI only, never business chat)                                                |
| Bookings      | `bookings`, `booking_items` (price lines copied at booking time), `booking_events` (history, trigger-written)                        |
| Payments      | `payments`, `payment_webhook_events` (verified webhooks only), `payouts`, `business_payout_accounts`                                 |
| Chat          | `conversations` (opens when a booking is confirmed), `messages`, `conversation_reads`, `chat_reports`, `user_blocks`                 |
| Reviews       | `reviews` (one per completed booking), `review_photos`                                                                               |
| Disputes      | `disputes`, `dispute_messages`, `dispute_evidence`, `dispute_events`                                                                 |
| Notifications | `notifications` (in-app), `notification_deliveries` (email/SMS/push outbox)                                                          |
| Revenue       | `subscription_plans`, `business_subscriptions`, `featured_packages`, `featured_placements`, `business_charges`                       |
| Platform      | `platform_settings` (commission, booking fee), `admin_actions` (audit log), `security_events`, `rate_limit_hits`, `analytics_events` |

## Statuses

| Type                  | Values                                                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `user_status`         | active, suspended, deactivated                                                                                                                                |
| `business_status`     | draft, pending, under_review, approved, rejected, suspended. Only **approved** is ever public or seen by the AI                                               |
| `booking_status`      | requested, pending_provider, quoted, accepted, payment_pending, confirmed, in_progress, completed, reviewed, cancelled, declined, expired, disputed, refunded |
| `payment_status`      | pending, success, failed, abandoned, refunded, partially_refunded                                                                                             |
| `payout_status`       | pending, processing, paid, failed, on_hold                                                                                                                    |
| `conversation_status` | open, closed, locked                                                                                                                                          |
| `dispute_status`      | open, under_review, escalated, resolved, closed                                                                                                               |

The booking flow is `requested → pending_provider → accepted → payment_pending → confirmed →
in_progress → completed → reviewed`, with `quoted` for quote requests. The allowed moves are in
`is_valid_booking_transition`; anything else is refused by the `guard_booking_changes` trigger.

## Who can see what

| Data                                   | Customer                     | Business owner                                    | Visitor | Admin (server)                                     |
| -------------------------------------- | ---------------------------- | ------------------------------------------------- | ------- | -------------------------------------------------- |
| Approved businesses, services, reviews | Yes                          | Yes                                               | Yes     | Yes                                                |
| Other businesses (draft, pending…)     | No                           | Their own only                                    | No      | Yes                                                |
| A booking                              | Their own                    | Bookings for their business                       | No      | Yes                                                |
| Booking street address                 | Their own                    | Only once confirmed (paid), via `booking_address` | No      | Yes                                                |
| Customer email and phone (`users`)     | Their own                    | **Never**                                         | No      | Yes                                                |
| Chat messages                          | Their own chats              | Their own chats                                   | No      | Only with a report or dispute on that chat, logged |
| AI conversations                       | Their own                    | No                                                | No      | No                                                 |
| Payments                               | Their own (no checkout link) | Through payouts                                   | No      | Yes                                                |

## Functions clients can call

| Function                                                   | What it does                                                            |
| ---------------------------------------------------------- | ----------------------------------------------------------------------- |
| `match_businesses(...)`                                    | Search and matching over approved, open businesses only                 |
| `get_business_stats(business)`                             | Public figures for a profile (completed bookings, price range, ratings) |
| `get_public_reviews(business, limit, offset)`              | Published reviews                                                       |
| `concierge_provider_details(business)`                     | One eligible business's details for the AI Concierge                    |
| `booking_address(booking)`                                 | The street address, under the visibility rule above                     |
| `get_booking_counterparts(user_ids)`                       | Name and photo (only) of people you have a booking with                 |
| `mark_conversation_read(conversation)`                     | Read receipts                                                           |
| `current_plan_code(business)`, `is_featured_now(business)` | Revenue status of your own business                                     |

Everything else that changes money or status (`create_booking`, payment and payout functions,
`hit_rate_limit`, statistics for admins) runs as the service role from server code only.

## Storage buckets

| Bucket                   | Public | Who can read                        |
| ------------------------ | ------ | ----------------------------------- |
| `avatars`                | Yes    | Everyone                            |
| `business-media`         | Yes    | Everyone (logos, covers, portfolio) |
| `review-photos`          | No     | Wherever the review is visible      |
| `chat-attachments`       | No     | The two people in that chat         |
| `dispute-evidence`       | No     | The two parties and admins          |
| `verification-documents` | No     | The business owner and admins       |

Every upload is checked by its first bytes on the server, and fakes are deleted (`src/lib/security/files.ts`).

## Scheduled jobs (pg_cron)

| Job                       | Schedule        | What it does                                         |
| ------------------------- | --------------- | ---------------------------------------------------- |
| `scheduled-notifications` | Every 15 min    | Booking reminders and review requests                |
| `billing-reminders`       | Hourly          | Subscription and featured placement renewals         |
| `rate-limit-cleanup`      | Hourly          | Deletes old rate limit counts                        |
| `analytics-retention`     | Daily 03:30 UTC | Deletes analytics events past their retention period |

## Tests

`supabase/tests/*.test.sql` (pgTAP, `npm run db:test`) sign in as each kind of user and check the
rules above directly against the database: `access_control`, `security`, `product_rules`,
`booking_engine`, `payments`, `chat`, `reviews`, `disputes` and others.
